HONEST INTERPRETATION
=====================
1. The DISCRIMINATING signal is scrollbarWidth / scrollbarColor:
     BEFORE: thin / rgb(42,42,58) transparent   → both NON-auto.
     AFTER:  auto / auto                          → both auto.
   Per MDN (https://developer.mozilla.org/en-US/docs/Web/CSS/::-webkit-scrollbar):
   "If an element's computed scrollbar-color and scrollbar-width values are
   anything other than auto, they will override ::-webkit-scrollbar-* styling."
   BEFORE, those values are non-auto (thin + a token color) on every element via
   the inherited `*` rule → the override condition is ACTIVE → the webkit rules,
   though present, do not govern the painted scrollbar. AFTER, the @supports
   split removes the standard `*` rule on this (WebKit) engine, so both revert to
   `auto` → the override condition is GONE → the ::-webkit-scrollbar-* rules
   govern. This flip is exactly the mechanism the ticket describes, and it is
   observed here as a real BEFORE≠AFTER delta.

2. IMPORTANT CAVEAT — the pseudo-element computed values are NOT discriminating:
   getComputedStyle(el,'::-webkit-scrollbar').width reads 6px, and the thumb bg
   (rgb(42,42,58)) and radius (3px) read the authored values, in BOTH the broken
   BEFORE state and the fixed AFTER state. Chromium returns the authored
   ::-webkit-scrollbar-* declarations in computed style regardless of whether the
   scrollbar-color/width override actually suppresses their PAINTING. So a probe
   that only checked `::-webkit-scrollbar width == 6px` would pass in BOTH states
   and prove nothing. The primary verification probe (probe-chromium.txt) is
   therefore sound specifically because it also asserts scrollbarWidth == auto AND
   scrollbarColor == auto — the two values that actually change between broken and
   fixed. This differential is what justifies that choice of assertions.

3. gutter == 0 in both states: headless Chromium uses overlay scrollbars (no
   space-taking gutter), independent of the fix. Not discriminating; recorded for
   completeness, not relied upon.

CONCLUSION: the differential CONFIRMS the ticket's override theory on the
discriminating axis (scrollbarWidth/scrollbarColor: thin/token → auto/auto), and
simultaneously shows that the ::-webkit-scrollbar computed width is a non-
discriminating signal — which is why the acceptance probe keys on the standard
properties reverting to `auto`, not on the pseudo-element width alone.
